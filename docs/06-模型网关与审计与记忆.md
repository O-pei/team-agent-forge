## 2. 模型网关

### 2.1 SPI 契约（冻结）

`agentforge-audit/src/main/java/com/agentforge/audit/gateway/`：

```java
public record ChatModelInfo(Long id, String name, String provider, String modelName,
                            boolean defaultModel, boolean enabled) {}

public interface ModelProviderFactory {
    ChatModel getChatModel(Long id);      // 按 id 取；id 为 null 取默认模型
    ChatModel getDefaultChatModel();
    Long getDefaultModelId();
    ChatModelInfo getModelInfo(Long id);
}
```

Agent 侧通过 `ObjectProvider<ModelProviderFactory>` 注入，缺失时回退 `MockChatModel`，保证零配置可跑（`ReactAgentFactory#resolveChatModel`）。

### 2.2 包装链

```
                       ┌──────────────────────────────┐
Agent ──► ChatModel ──►│ UsageRecordingChatModel       │──► 真实 ChatModel
                       │  (采集 prompt/completion/延迟) │     ├─ MockChatModel
                       │  缺失 usage 时 chars/4 估算   │     └─ DashScopeChatModel
                       └──────────────┬───────────────┘
                                      │ TokenUsageEvent（线程内组装）
                                      ▼
                       TokenUsageServiceImpl.record()  @Async("tokenUsageExecutor")
                                      │
                                      ▼
                              ai_token_usage 表
```

- `ModelProviderFactoryImpl`：解析 `ai_model` 配置 → 创建底层 `ChatModel` → 用 `UsageRecordingChatModel` 包装后返回；按模型 id 缓存（`ConcurrentHashMap`），模型增删改后 `evict(id)` / `evictAll()`。
- 底层解析顺序（`resolveConfig(Long id)`）：
  1. 传 id：`findById` 且 `enabled=true`，否则回退“默认模型”，再否则首个启用模型；
  2. 不传 id：`findFirstByDefaultModelTrueAndEnabledTrueOrderByIdAsc()`，再否则首个启用模型；
  3. 都找不到：WARN + `MockChatModel()`（不抛异常，保证可用）。

### 2.3 Provider 分支

| provider | 实现 | 关键行为 |
| --- | --- | --- |
| `MOCK` | `MockChatModel` | 本地回显 + 模拟 usage；默认模型种子即 MOCK |
| `DASHSCOPE` | `spring-ai-alibaba-starter-dashscope` 的 `DashScopeChatModel` | 从 `ai_model.api_key_encrypted` 解密 API Key；`baseUrl` 可选；`model/temperature/maxTokens` 来自配置 |
| `OPENAI_COMPATIBLE` | — | **未实现**：WARN 后回退 `MockChatModel`（v0.2 计划） |

DASHSCOPE 分支关键点：

- API Key 缺失 / 解密失败 / 构建异常：WARN + 回退 Mock，**不阻断请求**；
- 日志示例（不含明文 Key）：
  ```
  WARN  ModelProviderFactoryImpl - 模型 ID=2 未配置 API Key，回退 MockChatModel（provider=DASHSCOPE）
  WARN  ModelProviderFactoryImpl - 创建 DashScope ChatModel 失败（modelId=2），回退 MockChatModel: ...
  ```
- **重要（与直觉不同）**：工厂只读取数据库 `ai_model.api_key_encrypted`，不读取环境变量 `AI_DASHSCOPE_API_KEY`。`application.yml` 中的 `spring.ai.dashscope.api-key: ${AI_DASHSCOPE_API_KEY:sk-agentforge-development-placeholder}` 仅服务于 Spring AI 自动配置占位，不会被 `ModelProviderFactoryImpl` 使用。因此接入真实模型时必须在模型配置里填写 `apiKey`（见 2.6）。

### 2.5 Mock 行为

- 非流式 `call`：返回
  `（Mock 模型）已收到你的消息：<最后一条 user 文本>` + 换行 + 提示“当前未配置真实模型，请在「模型配置」中添加 DashScope/OpenAI 兼容模型，或设置环境变量 AI_DASHSCOPE_API_KEY。”
- 流式 `stream`：把固定文案按 `max(4, 文本长度/8)` 步长切块逐块下发，最后一块带 usage；
- usage：没有真实 token 时按 `chars / 4` 估算（最少 1），保证审计记录不为 0。

创建/更新规则：
- `provider` 只接受 `MOCK` / `DASHSCOPE` / `OPENAI_COMPATIBLE`，否则 `40000`；

1. 设置环境变量（PowerShell）：`$env:AI_DASHSCOPE_API_KEY='sk-...'`；`application.yml` 的 `spring.ai.dashscope.api-key` 读取该变量。
2. 创建 DASHSCOPE 模型（**必须带 apiKey**，否则工厂回退 Mock）：
   ```http
   POST /api/v1/models
   {
     "name": "DashScope Qwen Plus",
     "provider": "DASHSCOPE",
     "modelName": "qwen-plus",
     "baseUrl": "https://dashscope.aliyuncs.com",
     "apiKey": "sk-...",
     "enabled": true,
     "defaultModel": true,
     "temperature": 0.7,
     "maxTokens": 2048
   }
   ```
3. 设为默认：上面 `defaultModel=true` 即自动切换；也可 `PUT /api/v1/models/{id}` 修改。
4. 验证：`POST /api/v1/models/{id}/test` 返回真实回显；调用 Agent 后在 `/api/v1/audit/usage/records` 看到 `provider=DASHSCOPE` 的真实 token 记录。
5. 无真实 Key / 断网时：保持默认 MOCK 即可，工厂不会因外网失败而报错（DASHSCOPE 构建或调用异常会降级 Mock）。

计费种子（V2）：`DASHSCOPE` / `qwen-plus` 输入 `0.004`、输出 `0.012`（元/千 token，CNY），MOCK 全 0。

### 2.8 密钥加密 `CryptoUtils`

`agentforge-common/src/main/java/com/agentforge/common/crypto/CryptoUtils.java`（全项目唯一实现，`rag`、`datasource` 复用）：

- 算法：`AES/GCM/NoPadding`，12 字节随机 IV，128 位 tag；
- 密文格式：`v1:` + `Base64(IV ‖ ciphertext)`；解密兼容无 `v1:` 前缀的旧数据；
- 密钥：系统属性 `agentforge.crypto.key` > 环境变量 `AGENTFORGE_CRYPTO_KEY` > 开发默认值 `agentforge-dev-only-crypto-key-change-me`（`application.yml` 注释标明“仅开发”）；实际 AES Key 由 `SHA-256(原始字符串)` 派生；
- API：`static String encrypt(String plain)`、`static String decrypt(String cipher)`、`static void configure(String key)`、`static boolean explicitlyConfigured()`；空值返回 null；
- 日志禁止输出明文/密文；生产必须通过环境变量覆盖默认密钥，否则已加密数据在换密钥后不可解。

### 3.2 采集链路与 `UsageContext`

`agentforge-audit/src/main/java/com/agentforge/audit/usage/UsageContext.java`：

```java
public final class UsageContext {
    public static void open(Long tenantId, Long userId, Long agentId, Long runId, String sessionId);
    public static Context current();   // 无上下文返回 null
    public static void close();        // HOLDER.remove()，必须与 open 成对
    public record Context(Long tenantId, Long userId, Long agentId, Long runId, String sessionId) {}
}
```

- 基于 `ThreadLocal<Context>`；仅当前请求线程可见，**不跨线程**（异步任务不会自动继承）；
- Agent 入口 `AgentExecutionService`：`bindRunThread()` 中 `UsageContext.open(...)`，`complete()` 的 `finally` 中 `UsageContext.close()` + `RunContextHolder.clear()`；运行统计同时写回 `af_agent_run` 的 prompt/completion/total。
- 采集侧字段优先级：`UsageContext.current()` 存在则取 tenant/user/agent/run/session；否则回退 `TenantContext.getCurrentTenantId()`、`UserContext.getUserIdOrNull()`。

### 3.3 `UsageRecordingChatModel`

构造：`(ChatModel delegate, Long modelId, String modelName, String provider, TokenUsageService tokenUsageService)`，实现 `ChatModel`。

- `call`：`delegate.call` → 取 `text` 与 `metadata.usage` → 记录 `stream=false, success=true`；异常记录 `success=false` 后原样抛出；
- `stream`：`delegate.stream` 的 `doOnNext` 累加文本、保存“最后一个有效 usage”；`doOnComplete` 记录 `stream=true, success=true`；`doOnError` 记录 `success=false`；
- usage 判定：`usage != null && (promptTokens>0 || completionTokens>0 || totalTokens>0)`；缺失时按 `chars/4`（`UsageEstimator`，最少 1）估算；
- 总 token 兜底：`totalTokens = promptTokens + completionTokens`（当底层未给 total）；
- 组装 `TokenUsageEvent`，`traceId = MDC.get("traceId")`，调用 `TokenUsageService.record(event)`。

### 3.4 `TokenUsageEvent` 字段

```java
public record TokenUsageEvent(
    Long tenantId, Long userId, Long agentId, Long runId, String sessionId,
    Long modelId, String modelName, String provider,
    long promptTokens, long completionTokens, long totalTokens,
    boolean stream, boolean success, long latencyMs, String traceId) {}
```

### 3.5 异步落库与计费

`AuditConfig`（audit 模块）：

| Bean | 参数 |
| --- | --- |
| `tokenUsageExecutor` | core 2 / max 4 / queue 2000 / keepAlive 60s / 前缀 `token-usage-` / 拒绝策略 `CallerRunsPolicy`（队列满时由调用线程执行，不丢记录）/ 关闭等待 5s |
| `CryptoUtils` | 启动时 `CryptoUtils.configure(agentforge.crypto.key)`，保证解密前密钥就绪 |

`TokenUsageServiceImpl`：

```java
@Async("tokenUsageExecutor")
public void record(TokenUsageEvent event);   // void，异常只 WARN，不影响主链路
```

- `tenantId` 为空时默认 `1`；
- 计费（**v0.1.0 已实现，不是计划项**）：
  ```
  price = ai_model_price.findFirstByProviderIgnoreCaseAndModelNameIgnoreCase(provider, modelName)
  cost  = inputPricePer1k  * promptTokens     / 1000
        + outputPricePer1k * completionTokens / 1000
  （BigDecimal，HALF_UP，保留 6 位；无价目配置则 cost=0）
  ```
- 失败日志（不重建数据、不重试）：
  ```
  WARN TokenUsageServiceImpl - Token 用量异步落库失败，已忽略: traceId=..., model=..., reason=...
  ```

`ai_model_price` 列：`id`、`provider`、`model_name`、`input_price_per_1k`、`output_price_per_1k`、`currency`（默认 `CNY`）、`created_at/updated_at/version`，唯一键 `(provider, model_name)`。种子：MOCK 0/0、DASHSCOPE `qwen-plus` 0.004/0.012。

### 3.6 查询 API

`AuditController`：`@RequestMapping("/api/v1/audit")`，类级 `@PreAuthorize("hasAuthority('audit:read')")`；`UsageQueryService` 负责聚合。

| 方法 | 路径 | 参数 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/v1/audit/usage/summary` | `from`、`to`（ISO LocalDateTime，可空） | `UsageSummary` |
| GET | `/api/v1/audit/usage/trend` | `from`、`to`、`granularity=day\|hour` | `List<TrendPoint>` |
| GET | `/api/v1/audit/usage/breakdown` | `from`、`to`、`groupBy=model\|agent\|user` | `List<BreakdownItem>` |
| GET | `/api/v1/audit/usage/records` | `page=1`、`size=10`（≤100）、`from`、`to`、`modelId`、`agentId`、`userId` | `PageResult<UsageRecordResponse>` |
| GET | `/api/v1/audit/usage/export` | `from`、`to` | `text/csv`，文件名 `token-usage.csv` |
| GET | `/api/v1/audit/overview` | 无 | `AuditOverview` |

时间范围规则：`to` 默认当前时间 +1s，`from` 默认 `to - 30 天`；`from >= to` → `40000 时间范围不合法：from 必须早于 to`；`granularity` 非 day/hour → `40000 granularity 仅支持 day / hour`；`groupBy` 非三者 → `40000 groupBy 仅支持 model / agent / user`；`size > 100` 截断为 100。

返回字段（真实 DTO，逐字）：

- `UsageSummary(totalPromptTokens, totalCompletionTokens, totalTokens, totalCost, requests)`

### 3.7 已知问题（收尾复测项）

在本地 18080 的实测实例上，`/audit/usage/summary` 与 `/audit/overview` 的聚合值返回 0，而同库 `/records`、`/trend` 有数据，说明写入与时间过滤正常、问题局限在聚合方法本身。根因高度疑似 `TokenUsageRepository.summarize(...)` 以单元素 `Object[]` 接收多列聚合行时被 Spring Data 包装成“行数组”（长度 < 5），命中 `UsageQueryService.summary` 的 `row.length < 5` 兜底分支返回 0；`/overview` 复用 `summary` 故同样为 0。**v0.1.0 发布前需修复并复测**：把返回类型改为 `List<Object[]>` 后取首行（或改用 `Object[]` 单列 projection/`Tuple`），并在 CI 加一条“写入 N 条 → summary 非零”的集成断言。本文档不以该异常修改接口字段。

## 4. 记忆引擎

### 4.1 三层结构

```
┌─ 会话层（Agent 运行时）────────────────────────────────────────┐
│ af_agent_message（MySQL/H2）：持久化 user/assistant 消息       │
│ SAA MemorySaver（进程内 checkpointer）：图执行中间状态，threadId=sessionId │
├─ 短期记忆层（本模块 SPI）────────────────────────────────────┤
│ MemoryStore：RedisMemoryStore（TTL 7d / 200 条）或 InMemory 兜底 │
├─ 长期事实层（本模块 SPI）────────────────────────────────────┤
│ LongTermMemory：RedisFactRepository（Hash）或 InMemoryFactRepository │
└────────────────────────────────────────────────────────────────┘
```

Agent 侧实际链路：`AgentExecutionService` 启动时 `saveMessage("user")` 落 `af_agent_message`，结束时落 `assistant`；`ReactAgentFactory` 为每个 Agent 创建 `new MemorySaver()` 作为图 checkpointer；工具 `remember_fact` / `recall_facts` 通过 `LongTermMemory` 读写长期事实。

> 注意：`MemoryStore` 的写入方尚未接入 Agent 运行时（Agent 直接写 `af_agent_message`）。`/api/v1/memory/sessions/{id}/messages` 读取的是 `MemoryStore`（Redis list / 内存 deque），当前通常为空；接入计划见 §6。

### 4.2 SPI

```java
// agentforge-memory/src/main/java/com/agentforge/memory/spi/MemoryStore.java
public interface MemoryStore {
    void appendMessage(String sessionId, MemoryMessage message);
    List<MemoryMessage> getRecentMessages(String sessionId, int limit);
    void clearSession(String sessionId);
    default boolean persistent() { return false; }   // Redis=true，内存=false
}

public record MemoryMessage(String role, String content, Instant createdAt,
                            Map<String,Object> metadata) {}
public interface LongTermMemory {
    void saveFact(Long tenantId, Long userId, String fact, String category, double confidence);
    List<LongTermFact> recall(Long tenantId, Long userId, String query, int topK);
}
public record LongTermFact(Long id, String fact, String category, double score,
                           Instant createdAt) {}
```

### 4.3 会话短期存储

| 实现 | 存储 | 容量 | TTL | 说明 |
| --- | --- | --- | --- | --- |
| `RedisMemoryStore` | Redis List，key `agentforge:memory:session:{sessionId}` | 保留最近 200 条（`LTRIM -200 -1`） | 7 天（每次 append 续期） | 消息 JSON：`{role,content,createdAt,metadata}`；`persistent()=true` |
| `InMemoryMemoryStore` | `ConcurrentHashMap<String, Deque<MemoryMessage>>` | 200 条/会话 | 7 天（惰性清理：读取/写入时丢弃过期头部） | 进程重启即丢；`persistent()=false` |

`getRecentMessages` 语义：取最近 `limit` 条（Redis 用 `LRANGE -limit -1`），`limit<=0` 返回空；内存实现按插入顺序截取末尾。

### 4.4 长期事实存储与召回

事实记录 `FactRecord(id, tenantId, userId, fact, category, confidence, createdAt)`：

| 实现 | key / 结构 | 说明 |
| --- | --- | --- |
| `RedisFactRepository` | Hash `agentforge:memory:facts:{tenantId}:{userId}`，field=事实 id，value=JSON；id 由 `agentforge:memory:fact:id` 的 `INCR` 生成 | TTL 7 天；Redis 异常 WARN 后吞掉（记日志不阻断） |
| `InMemoryFactRepository` | `ConcurrentHashMap<String, Map<Long, FactRecord>>`，scope key `tenantId:userId` | 自增 `AtomicLong`；重启丢失 |

召回算法（`LongTermMemoryImpl`）：

```
score = 0.7 * similarity(fact, query) + 0.3 * confidence
query 为空时 score = confidence
过滤 score > 0.01 → 按 score 降序、createdAt 降序排序 → 取 topK → score 保留 4 位小数
```

`MemorySimilarity`（词面 Jaccard，不是 embedding）：

- 中文字符：单字 token；相邻两个中文字符再组成 bigram（如“北京/京大/大学”）；
- 英文/数字：按非字母数字切词、转小写；
- `similarity = |交集| / |并集|`，并集为空返回 0。

`saveFact` 规则：`category` 空 → `general`；`confidence` 截断到 `[0,1]`；`fact` 空则不保存。

### 4.5 配置与降级

`application.yml`：

```yaml
agentforge:
  crypto:
    key: ${AGENTFORGE_CRYPTO_KEY:agentforge-dev-only-crypto-key-change-me}  # 仅开发默认值
  memory:
    redis-enabled: ${AGENTFORGE_REDIS_ENABLED:false}
    short-term-max-messages: 20
    summary-threshold: 30
  audit:
    alert-threshold: 0.8
    flush-interval-ms: 2000
management:
  health:
    redis:
      enabled: false     # 无 Redis 时避免 health DOWN
```

降级逻辑（`MemoryConfig` + `MemoryRedisSupport`）：

1. `agentforge.memory.redis-enabled=false` → 直接 InMemory，INFO：
   `agentforge.memory.redis-enabled=false，记忆引擎使用 InMemoryMemoryStore（进程内记忆）`
2. 开启但容器无 `StringRedisTemplate` → InMemory，WARN：
   `Redis 已启用但容器中未装配 RedisTemplate，记忆引擎自动降级为 InMemoryMemoryStore（进程内记忆，重启不保留）`
3. 开启且 `PING` 成功（1.5s 超时）→ Redis，INFO：`Redis 连接探测成功，记忆引擎使用 RedisMemoryStore（TTL 7 天，保留最近 200 条）`
4. 开启但探测失败 → InMemory，WARN：
   `Redis 不可用（agentforge.memory.redis-enabled=true 但连接失败），记忆引擎自动降级为 InMemoryMemoryStore；进程重启后会话记忆与长期记忆将丢失。如需持久化请启动 Redis 后重启服务。`

`MemoryConfig` 通过 `@Bean @Primary` 暴露 `MemoryStore` 与 `FactRepository`；`StringRedisTemplate` 用 `ObjectProvider` 可选注入，**启动不因 Redis 缺失失败**。

`MemoryAdminService` 规则：
- 消息分页：`size > 100` 截断，读 `MemoryStore.getRecentMessages` 后在内存窗口（≤200 条）内做分页；
- 会话摘要：取最近 **4 条**消息拼成 `role: content`，超过 **500 字**截断（`...`）；**不是 LLM 摘要**，只是可读预览；
- 事实列表：以 `keyword` 调 `LongTermMemory.recall(tenant, user, keyword, 200)`，再内存分页；`userId` 为空时回退当前登录用户；
- 删事实：不属于当前 tenant/user → `40400 记忆不存在或无权访问: {id}`。

### 4.7 接入真实 Redis

本机无 Docker 时，Windows 可用 Memurai / WSL2 / 远程 Redis；生产推荐 `docker compose up -d redis`：

```bash
docker run -d --name agentforge-redis -p 6379:6379 \
  -v agentforge-redis:/data redis:7-alpine
```

`.env` / 环境变量：`AGENTFORGE_REDIS_ENABLED=true`；`application.yml` 的 `spring.data.redis.host/port` 指向实例（本机 6379）。重启后启动日志出现 `Redis 连接探测成功…`，`GET /api/v1/memory/facts` 与 `sessions/*/messages` 开始返回 Redis 数据；健康检查 `management.health.redis.enabled=false` 保持不变（由本模块自行探测，避免降级时 health DOWN）。

### 4.8 已知限制

1. 召回是**词面 Jaccard**，没有 embedding 语义召回；同义改写（“住址” vs “家”）召不回，v0.2 计划接入向量检索。
2. `MemoryStore` 尚未接入 Agent 运行时写入（见 §4.1），管理端会话消息当前依赖 `af_agent_message` 的其它查询；`RedisMemoryStore` 仅在直接调用 SPI 时生效。
3. Redis 降级为进程内后：重启丢失、多实例不共享；生产必须开 Redis。
4. `OPENAI_COMPATIBLE` provider 未接入，创建后会回退 Mock。
5. 计费依赖静态价目表，无折扣/阶梯价/预算告警；`agentforge.audit.alert-threshold`、`flush-interval-ms` 为预留配置，**v0.2 计划**实现告警与批量 flush（当前逐条异步落库）。
6. 会话摘要为截断拼接，非 LLM 归纳（v0.2 计划异步生成并缓存）。
7. `/audit/usage/summary`、`/audit/overview` 的本地聚合异常见 §3.7，待最新构建复测。

## 5. 扩展指南

### 5.1 新增 Provider

1. 在 `ModelProviderFactoryImpl` 增加常量与 `switch` 分支，构造对应 `ChatModel`（可参考 `buildDashScopeModel`）；
2. 通过 `UsageRecordingChatModel` 包装返回，**不要绕过审计**；
3. `ai_model` 无需改表（`provider` 为 VARCHAR）；若新 provider 需要新配置项，优先放进 `base_url`/`model_name`，否则走 V3+ 迁移并同步 `ModelConfigRequest`；
4. `ai_model_price` 增加价目种子，否则 cost=0；
5. 补单测：无 Key 回退 Mock、正常构造、`evict` 生效。

### 5.2 新增审计维度

1. 迁移新增列（同时兼容 H2/MySQL，`DATETIME`/`TEXT`/`BOOLEAN`），同步 `TokenUsageEvent`、`TokenUsageEntity`；
2. `UsageRecordingChatModel` 负责采集（如从 `UsageContext` 扩展 `departmentId`）；
3. `TokenUsageRepository` 的 `summarize` / `findRows` 增加聚合列，`UsageQueryService` 增加 `groupBy` 分支或新查询参数；
4. `UsageRecordResponse` / `UsageSummary` / `BreakdownItem` 扩展字段（新字段追加，不破坏既有 JSON）；
5. 前端表格列与导出 CSV 表头同步；CI 加字段断言。

### 5.3 替换记忆后端

1. 实现 `MemoryStore`（`persistent()=true`）或 `LongTermMemory`/`FactRepository`；
2. 在 `MemoryConfig` 的 `@Bean @Primary` 处按配置选择实现（参考 `MemoryRedisSupport.probe` 的探测模式），**不要**在业务代码里 `if (redis)` 判断；
3. 保持 key 前缀 `agentforge:memory:` 与 TTL 7 天约定；新增后端必须补降级日志与集成测试；
4. 管理端 `/api/v1/memory/**` 无需改动（只依赖 SPI）。

### 6.3 常见问题

- **调用模型总返回 Mock 文案**：检查默认模型是否 `enabled=true`、DASHSCOPE 模型是否填了 `apiKey`、日志是否有 `回退 MockChatModel` WARN。
- **审计记录为 0 tokens**：MOCK 也有 chars/4 估算；若整条记录缺失，看 `Token 用量异步落库失败` WARN 与线程池队列。
- **日志有 Redis 降级 WARN 但接口正常**：预期行为；需要持久化就启动 Redis 并设 `AGENTFORGE_REDIS_ENABLED=true` 后重启。
- **模型配置改完不生效**：保存会 `evictAll()`；若仍旧，确认请求打到了同一实例（多实例部署见 v0.2 缓存广播计划）。
