# AgentForge 开发路线图（v1.0）

> 配套文档：[`01-技术方案.md`](./01-技术方案.md) · [`research/SAA-1.1.2-API.md`](./research/SAA-1.1.2-API.md) · [`research/spring-ai-1.1-api.md`](./research/spring-ai-1.1-api.md)
> 状态：定稿（2026-10-29）；执行方式：**多智能体并行开发**，每个阶段跑通「可演示闭环」再进入下一阶段。

---

## 0. 交付目标与里程碑

**v0.1.0 定义（开源首发版）**：`git clone` → `mvn spring-boot:run`（H2 + Mock 模型 + 可选 Redis）→ 浏览器完成「注册/登录 → 建知识库 → 传文档 → 创建 Agent → 多轮对话（流式、引用、工具调用）→ 查看 Token 消耗与 RBAC 管理」完整闭环。

| 里程碑 | 对应阶段 | 验收标志 |
| --- | --- | --- |
| **M1 工程可跑** | P0 | 父 POM 编译通过；后端启动 `/actuator/health=UP`；前端 `pnpm build` 通过；CI 绿灯 |
| **M2 账号与治理** | P1 + P2 | 邮箱验证码注册/登录、JWT 刷新、RBAC 生效；聊天链路产出 Token 用量明细与看板 |
| **M3 智能体能力** | P3 + P4 + P5 + P6 | 记忆/RAG/数据源/沙箱/多智能体编排全部接入 Agent，SSE 流式可审批 |
| **M4 开源发布** | P7 + P8 + P9 | 前端全功能、测试与安全加固完成、README 5 分钟跑通、GitHub v0.1.0 Release |

## 4. Definition of Done（每个任务）

1. 代码 + 单测（核心逻辑）通过 `mvn -pl <module> test` / `pnpm build`；
2. 接口在 Swagger 或前端页面可验证；
3. 涉及表结构必须走 Flyway 迁移（禁止 `ddl-auto=update`）；
4. 涉及权限的接口标注权限码并加测试；
5. 涉及模型/工具/沙箱调用必须产生 Token/审计记录；
6. 更新对应文档（API/README/ADR）。

---

## 5. v0.1.0 范围边界

**做**：上述 P0~P9 的 v1 简化版；单租户默认可多租户字段；H2 + Mock 模型零依赖可跑；Process 沙箱（Docker 沙箱代码交付但不强依赖）。

**不做（v0.2+ backlog）**：可视化拖拽编排器、多实例集群与 K8s Operator、短信登录真实通道、计费支付、Elasticsearch/BM25 生产级混合检索、Redis Stack 原生向量索引、浏览器自动化沙箱、审批流引擎（BPMN）。

## 6. 风险与应对（执行视角）

| 风险 | 触发点 | 应对 |
| --- | --- | --- |
| SAA API 与文档不一致 | P0-2/P6-2 | 已完成 API 调研（见调研报告）；先写最小 `ReactAgent` spike 再铺开 |
| 流式 Token 统计缺失 | P2-5 | Advisor 自行聚合 chunk usage + 模型侧兜底估算；单测覆盖 |
| 无 Docker | P5-6 | Process 沙箱默认；Docker 实现仅编译 + 文档；CI 不跑容器 |
| 无模型 Key | P2-3 | Mock 模型全链路；Key 到位后仅改配置 |
| 本机无 Redis | P3 | 下载 redis-windows 8.10.3 本地启动；代码层 `InMemoryMemoryStore` 降级 |
| 前端/后端接口漂移 | P6/P7 | P0 冻结 OpenAPI 契约；前端用 `openapi-typescript` 生成类型 |
| 范围过大 | 全程 | 每阶段可演示闭环；未完成能力进 backlog，不阻塞 M4 |
