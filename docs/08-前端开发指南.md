### 1.3 环境要求与安装

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 20（推荐 22 / 24） | 开发机实测 v24.14.0 |
| pnpm | ≥ 9（推荐 10.x） | 开发机实测 10.32.0；`packageManager` 字段未锁定，以 lockfile 为准 |
| 包管理器 | 仅 pnpm | 仓库内只有 `pnpm-lock.yaml`，不要用 npm/yarn 生成第二份 lock |

```bash
cd agentforge-ui
pnpm install          # 首次会下载 Vue/Element Plus/ECharts 等
pnpm dev              # http://127.0.0.1:5173
pnpm build            # vue-tsc --noEmit && vite build → dist/
pnpm typecheck        # 只做类型检查
pnpm preview          # 本地预览 dist，端口 4173
```

`.npmrc` 固定 `node-linker=hoisted`：pnpm 默认用 symlink/junction 组织 `node_modules`，某些 Node 版本（如本机 24.x）对 pnpm 虚拟目录的 realpath 解析异常，会报 `entities/decode is not defined by "exports"`、`Cannot find package 'picomatch'`。改成扁平安装可绕开。`package.json` 中 `pnpm.overrides.entities = ^7.0.1` 用于统一 `entities` 版本（markdown-it 的 dist 是自包含 bundle，不依赖外部 `entities` 运行时，升级安全）。**这两处是环境适配，不要随手删。**

源码统一 **UTF-8（无 BOM）**。Windows 上不要用 PowerShell 5.1 的 `Set-Content` 改源码（默认写 GBK/ANSI，会把中文和 UTF-8 字节写坏），用编辑器保存即可。

### 1.4 Vite 开发服务器与代理

`vite.config.ts` 关键配置：

- `server.host = '127.0.0.1'`，`server.port = 5173`，`strictPort = false`（5173 被占会顺延）。
- 代理：`/api` → `proxyTarget`，`changeOrigin: true`。
- `proxyTarget` 优先取**环境变量**，其次 `.env` 里的 `VITE_PROXY_TARGET`，默认 `http://127.0.0.1:8080`：

```ts
const env = loadEnv(mode, process.cwd(), '')
const proxyTarget = process.env.VITE_PROXY_TARGET || env.VITE_PROXY_TARGET || 'http://127.0.0.1:8080'
```

> 本机 8080 常被其它项目占用（实测会返回别的应用页面）。后端联调时用后端自定的端口 + 环境变量覆盖，例如后端跑在 18080：

```powershell
# PowerShell（仅当前窗口生效）
$env:VITE_PROXY_TARGET = 'http://127.0.0.1:18080'
pnpm dev
```

```bash
# bash / Git Bash
VITE_PROXY_TARGET=http://127.0.0.1:18080 pnpm dev
```

排查代理是否指向了"假后端"：`curl http://127.0.0.1:5173/api/v1/auth/me`，正常应返回 AgentForge 的 `{"code":40100,...}`，而不是第三方页面。

## 2. 请求层、认证与权限

### 2.1 调用链

```text
view ──► src/api/xxx.ts (路径+类型) ──► http (request.ts) ──► axios ──► /api/v1/**
                                          ├─ 请求拦截：注入 Authorization: Bearer
                                          ├─ 响应拦截：解包 ApiResponse.data
                                          ├─ code=40100/40101 → 单飞刷新 token → 重放一次
                                          └─ 其它错误 → ApiError + ElMessage(可静默)
```

页面里拿到的已经是 `data` 本体（不是 `ApiResponse`），因此调用方不需要再判 `code === 0`；失败统一走 `catch`。

### 2.2 `src/utils/request.ts`

| 导出 | 位置 | 说明 |
| --- | --- | --- |
| `API_BASE` | `request.ts:23` | `import.meta.env.VITE_API_BASE \|\| '/api/v1'` |
| `NETWORK_ERROR_CODE` | `request.ts:26` | `-1`：无响应/连不上后端 |
| `ApiError` | `request.ts:28` | `Error` 子类，带 `code`/`traceId` |
| `isApiResponse` | `request.ts:57` | 判定是否后端标准响应壳 |
| `notify` | `request.ts:66` | 统一错误提示；`silent` 与 401 系错误不弹 |
| `refreshAccessToken` | `request.ts:78` | 手动 axios 调 `/auth/refresh`，避免拦截器递归 |
| `forceLogin` | `request.ts:98` | 动态 `import('@/router')` 后跳 `/login?redirect=当前地址` |
| `handleUnauthorized` | `request.ts:114` | 单飞刷新 + 重放；失败则清 token 跳登录 |
| `http` | `request.ts:195` | 类型化客户端：`request/get/post/put/patch/delete` |
| `isFallbackError` | `request.ts:198` | 判定"后端未就绪"，用于 mock 兜底 |
| `getErrorMessage` | `request.ts:210` | 取可展示错误文案 |

行为约定：

1. **响应解包**：`ApiResponse{code,message,data,traceId,timestamp}` 且 `code === 0` 时直接返回 `data`；`responseType: 'blob'` 时返回原始 `data`（导出 CSV 用）。
2. **401 处理**：命中 `code ∈ {40100, 40101}` 或 HTTP 401 时，若存在 refreshToken 且本次请求没重试过（`config._retried`），用**单飞 Promise** 刷新一次并携带新 token 重放；否则清 token、跳登录、抛 `ApiError(40100, '登录状态已失效，请重新登录')`。刷新接口本身用裸 axios（15s 超时），避免 401 递归。
3. **错误统一提示**：响应拦截器里 `notify()` 弹 `ElMessage.error`（`grouping: true`，3.5s，避免批量请求刷屏）。请求配置加 `{ silent: true }` 可静默——登录/注册/验证码/登出/刷新/取消运行等场景已默认静默，页面自己决定怎么提示。
4. **错误码**：优先用后端 `body.code`；没有 body 时按 HTTP 状态映射：401→40100、403→40300、404→40400、429→42900、≥500→50000、无响应→`-1`。`-1` 的文案会提示"无法连接后端服务，请确认后端已启动或检查 VITE_PROXY_TARGET"。
5. **兜底判定** `isFallbackError`：`-1`（连不上）、`40400`（后端还没有该接口）、`≥50000`（5xx/50000）、`50300`（依赖不可用）。只有这些才允许走 mock，`40000` 参数错误、`40300` 无权限、`40900` 冲突必须如实报错。

新增接口的写法（`src/api/`）：

```ts
// 只在 api 层写路径与类型；不要在这里 catch 异常
list(params: PageQuery) {
  return http.get<PageResult<ModelConfig>>('/models', { params })
},
```

路径**不带** `/api/v1` 前缀（`baseURL` 已包含）。需要后端未就绪时静默重试的接口（如文档轮询）传 `silent: true`。

### 2.3 `src/stores/auth.ts`（Pinia，setup 风格）

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `accessToken` / `user` / `roles` / `permissions` | ref | 登录态；token 与 user 从 localStorage 恢复 |
| `loaded` | ref | `/auth/me` 是否已成功拉取（守卫据此决定是否请求） |
| `mockMode` | ref | 是否处于 DEV 演示身份；为 true 时 `hasPermission` 恒真 |
| `isLoggedIn` | computed | `!!accessToken` |
| `isSuperAdmin` | computed | `roles.includes('SUPER_ADMIN')` |
| `displayName` / `roleLabels` / `permCount` | computed | 顶栏展示 |
| `hasPermission(code?)` | method `auth.ts:42` | `code` 为空→true；`mockMode` 或 `SUPER_ADMIN`→true；否则按权限码匹配（支持 `'*'`） |
| `hasRole(role)` | method `auth.ts:50` | 角色判断 |
| `applySession(result)` | method `auth.ts:54` | 写 token/user/roles/permissions 并置 `loaded` |
| `fetchMe()` | method `auth.ts:67` | `GET /auth/me` → `{user, roles, permissions}`；失败时若可兜底则用演示身份 |
| `login(payload)` | method `auth.ts:96` | `POST /auth/login`；契约登录响应不含 permissions，若缺失会补调一次 `fetchMe` |
| `logout()` | method `auth.ts:123` | 非演示模式先调 `POST /auth/logout`（失败忽略），再 `resetSession` |
| `resetSession()` | method `auth.ts:132` | 清空 refs、token、mock 来源 |

注意：

- 演示模式（`mockMode`）登录后拿到的是 **SUPER_ADMIN** 演示身份，用于后端未就绪时把 UI 走通；顶栏会显示"演示数据"标记。真实后端可用时不会进入该分支。
- 契约里的 `user.roles` 是权限展示的主要来源；`permissions` 只从 `/auth/me` 获取。

### 2.4 `v-perm` 按钮级权限

`src/directives/permission.ts` 注册为 `v-perm`（`main.ts` 中 `app.directive('perm', permissionDirective)`）：

```vue
<el-button v-perm="'user:write'" type="primary">新建用户</el-button>
<el-button v-perm="['rag:write']" link @click="upload">上传文档</el-button>
```

实现：`mounted` / `updated` 时若 `auth.hasPermission(binding.value)` 为假就 `el.style.display = 'none'`。

> 只是视觉隐藏，DOM 与组件逻辑仍在。**不要**把敏感数据的渲染依赖在 `v-perm` 上；真正的安全边界在后端 `@PreAuthorize`。需要彻底不渲染时用 `v-if="auth.hasPermission(...)"`。

当前使用点（便于对齐角色权限）：`agent:write`（Agents 新建/编辑/发布/删除）、`role:write`（角色）、`datasource:write` / `datasource:query`（数据源与 SQL）、`user:write`（用户）、`rag:write`（知识库/文档）、`model:write`（模型）、`datasource:query`（沙箱执行）。

### 2.5 路由守卫与菜单过滤

`src/router/index.ts`：`createWebHistory()`，路由 `meta` 扩展了 `title` / `permission` / `public` / `icon` / `group` / `hidden`。

`router.beforeEach`（`router/index.ts:149`）流程：

1. 设置 `document.title = '${title} · AgentForge'`。
2. `meta.public`（登录/注册/找回密码/404）直接放行；若已登录且 `loaded` 又访问 login/register → 重定向 `/dashboard`。
3. 无 `accessToken` → `/login?redirect=当前完整路径`。
4. `!loaded` → `await auth.fetchMe()`；失败则 `resetSession()` 并回登录页。
5. `meta.permission` 存在且 `!auth.hasPermission(...)` → `/403`（把权限码带到 query）。
6. 其它放行；`afterEach` 预留（目前只做占位）。

`MainLayout.vue` 菜单是**静态定义 + 权限过滤**（`MainLayout.vue:146` 的 `menu: MenuEntry[]`，过滤逻辑 `visibleMenu` 在 `:165`）：

- 一级项：`permission` 不满足则隐藏。
- 分组（如"系统管理"）：先按子项权限过滤，子项为空则整组隐藏。

> 当前未消费 `/auth/me` 返回的 `menus` 做动态路由；如果后端要改为"菜单驱动"，需替换 `menu` 常量与 `router` 注册逻辑（见 §4.3 第 2 条）。

## 3. SSE 流式对话

### 3.1 协议（来自契约 §2.6 / §3）

- **唯一入口**：`POST /api/v1/chat/stream`，请求头 `Authorization: Bearer <accessToken>`、`Content-Type: application/json`、`Accept: text/event-stream`。
- 请求体：`{ agentId, sessionId?, message, attachments? }`。
- 响应：`text/event-stream`，每事件 `event: <name>` + 单行 `data: <json>`，事件之间空行分隔；每 15s 一个 `ping`（无 data 或空 data，前端忽略）。
- 事件与处理：

| event | data 关键字段 | 前端处理 |
| --- | --- | --- |
| `run.started` | `runId, agentId, sessionId, model` | 记录 `runId`/`sessionId`，状态 `streaming` |
| `message.delta` | `content` | 追加到回答正文（增量） |
| `message.completed` | `content` | 以完整正文覆盖（防增量丢字） |
| `tool.call` | `toolName, arguments, riskLevel` | 新增"运行中"的工具卡片 |
| `tool.result` | `toolName, resultSummary, success, elapsedMs` | 回填同名运行中卡片；找不到则新增 |
| `citation` | `index, documentId, filename, chunkIndex, score` | 按 `index` 去重追加引用 |
| `usage` | `model, promptTokens, completionTokens, totalTokens, cost` | 会话用量行 |
| `interrupted` | `approvalId, toolName, arguments, reason` | 状态 `interrupted`，展示审批卡片 |
| `run.completed` | `runId, status, elapsedMs, usage` | `SUCCEEDED→completed`、`CANCELLED→cancelled`、其它→`error` |
| `error` | `code, message` | 状态 `error` + 错误文案 |
| `ping` | — | 忽略（保活） |

契约要求：**前端主动断开/停止时必须调 `POST /api/v1/runs/{runId}/cancel`**（见 3.3 `stop()`）。

### 3.2 传输层 `src/utils/sse.ts`

浏览器原生 `EventSource` 不支持 POST + 自定义 Header，因此用 `fetch` + `ReadableStream` 自己解析：

- `parseBlock(block)`（`sse.ts:23`）：收集 `data:` 行后 **`dataLines.join('\n')` 再 `JSON.parse`**（多行 data 是合法 SSE 语法，必须拼完再解析）；解析失败保留原始字符串；无 data 行返回 `null`；忽略 `:` 注释行；缺省 event 名为 `message`。
- `streamSse(options)`（`sse.ts:46`）：`fetch(url, { method: 'POST', headers, body: JSON.stringify(body ?? {}), signal })`；URL 不以 `http` 开头时补 `API_BASE`；非 2xx 时读 body 的 `code/message` 抛 `ApiError`（无 code 且 ≥500 → 50000）。
- 读取：`response.body.getReader()` + `TextDecoder('utf-8')`，缓冲按 `\n\n` 切块逐块回调，最后再解析一次尾部残块。
- `isAbortError`（`sse.ts:97`）：兼容 `DOMException.name === 'AbortError'` 与 message 含 "abort" 的实现差异。

### 3.3 状态机 `src/composables/useSse.ts`

`useSse()` 返回：

| 成员 | 说明 |
| --- | --- |
| `status` | `idle / connecting / streaming / interrupted / completed / cancelled / error` |
| `content` | 回答正文（markdown 源文本） |
| `toolCalls` | `ToolCallItem[]`：`{id, toolName, arguments?, riskLevel?, resultSummary?, success?, elapsedMs?, running}` |
| `citations` | `CitationItem[]`：`{index, documentId, filename?, chunkIndex?, score?}` |
| `usage` | `UsageInfo \| null` |
| `runId` / `sessionId` / `interrupted` / `errorMessage` / `elapsedMs` | 运行态字段 |
| `isStreaming` | 是否在流中（按钮禁用用） |
| `isMockStream` | `runId` 以 `mock-` 开头（演示流） |
| `start(payload: ChatRequest)` | 重置 → 连接 `/chat/stream` → 分发事件；`AbortError` 记为 `cancelled`；后端不可达则进入演示流 |
| `stop()` | `controller.abort()`；若 `runId` 非空且非演示流 → `POST /runs/{runId}/cancel`（失败忽略）；状态置 `cancelled` |
| `reset()` | 清空全部状态（新会话/清空对话用） |

事件分发在 `handleEvent`（`useSse.ts:84`），`start` 在 `useSse.ts:189`，`stop` 在 `useSse.ts:222`。

**演示流** `runMockStream`（`useSse.ts:236`）：仅在后端不可达（`isFallbackError`）且 `VITE_ENABLE_MOCK` 打开时启用。它按关键词模拟工具调用与引用（"知识/文档/售后/产品/检索/引用"→`knowledge_search` + citation；"sql/数据/查询/报表/分析"→`sql_query`），按 6 字符/24ms 输出增量，最后发 `usage` + `run.completed(SUCCEEDED)`，并把"对话流式"记入 `mockState`（顶栏可见）。

### 3.4 断线、取消与多行 data 约定

- **多行 data**：SSE 规范允许一个事件把 `data:` 拆成多行，接收方必须先把所有 `data:` 行拼成完整载荷再解析。前端在 `parseBlock` 里 `dataLines.join('\n')` 后才 `JSON.parse`（`sse.ts:23`）；后端当前每事件单行 JSON，但前端按多行兼容，避免后端换行格式化时直接解析失败。解析失败时保留原始字符串（不抛错），便于展示后端排障文本。
- **服务端主动 `error` 事件**：`useSse` 不抛异常，只把 `status` 置 `error` 并写入 `errorMessage`，页面按普通错误提示。
- **网络中断**：`fetch` 在连接中断时 reject，`start()` 的 catch 分支判定：`AbortError` → `cancelled`（用户主动停止）；后端不可达且允许兜底 → 演示流；其它 → `status='error'` + 可读文案。**不自动重连**——对话重发会重复计费/重复执行工具，是否重试交给用户决定。
- **主动停止 / 页面卸载**：`abort()` 中断读取，同时若已拿到 `runId` 且非演示流，调用 `POST /runs/{runId}/cancel`。契约明确要求断线时取消运行，这一步不能省（`useSse.ts:222`）。
- **断线恢复**：刷新页面或重连后按 `GET /runs/{runId}` 回放未完成运行的能力**尚未实现**（见 §4.3 第 1 条），当前只保证"停止即取消"。
- **心跳 `ping`**：后端 15s 一次，`useSse` 直接忽略。如需做"长时间无响应"提示，可基于 `ping` 做空闲超时检测（当前未做）。

### 3.5 页面接入 `src/views/Chat.vue`

- 顶部选 Agent（`GET /agents?page=1&size=100`），默认选第一个 `PUBLISHED`；清空按钮 `sse.reset()` + 清 `turns`。
- 每轮消息本地结构 `Turn{question, answer, toolCalls, citations, usage, elapsedMs, runId, mock, status, error, interrupted}`；流期间用 60ms 定时器把 `useSse` 的响应式状态快照进当前 `Turn`，流结束清定时器。
- 渲染：回答用 `renderMarkdown()`（markdown-it + highlight.js，链接 `target="_blank" rel="noopener noreferrer"`）；工具调用折叠面板展示参数 JSON、风险等级 tag、成功/失败、耗时；引用列表展示文件名/分块/相似度；底部显示 usage（模型、输入/输出/总 token、成本）与本次耗时。
- 审批卡片：`interrupted` 时出现"通过/拒绝"，调用 `POST /runs/{runId}/approve`（body `{approved, comment}`，见 `Chat.vue:309`）；演示模式下会提示"审批不落库"。
- 停止：`sse.stop()`（内部会 `cancel` 当前 run）；卸载时 `onBeforeUnmount` 清定时器并 `sse.stop()`，避免页面切走后连接悬挂。

已知未做（P7-4 后续项）：刷新页面后按 `GET /runs/{runId}` 恢复未完成运行、`attachments` 文件上传、MCP/工具管理页。

### 3.6 反向代理注意

SSE 要被反代"直通"：Nginx 必须 `proxy_buffering off`（或 `X-Accel-Buffering: no`），否则事件会被攒到响应结束才下发；同时放长 `proxy_read_timeout`（示例见 §5.5）。本地 Vite 代理默认不缓冲，可直接用。

`pnpm build` 先跑 `vue-tsc --noEmit`（类型错误即失败），再由 Vite 输出 `dist/`（`index.html` + `assets/`，vendor 按 vue/element/charts/markdown 分包）。

> 注意：Vite 构建需要 `esbuild` 子进程。若在**禁止 Node 创建子进程**的受限沙箱里执行，会报 `Error: spawn EPERM`（`ensureServiceIsRunning`）；这类环境请在常规开发机或 CI 中构建。首版前端构建已通过验收（`vue-tsc --noEmit && vite build`）。

部署为静态站点 + 反向代理（history 模式必须回退到 `index.html`），仓库目前没有内置 nginx 配置，以下为**示例**：

```nginx
server {
  listen 80;
  server_name agentforge.example.com;
  root /usr/share/nginx/html;   # 放 dist/ 的内容
  index index.html;

  # SPA history 路由回退
  location / {
    try_files $uri $uri/ /index.html;
  }

  # API + SSE：关闭缓冲，放长超时
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
  }

  # 带 hash 的静态资源可长缓存；index.html 不缓存
  location ~* \.(js|css|woff2?|png|svg)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
  }
  location = /index.html {
    add_header Cache-Control "no-store";
  }
}
```

生产环境 `VITE_API_BASE` 用默认 `/api/v1`，由同域反代转发到后端即可；跨域直连需在后端配 CORS（不推荐）。

### 5.6 CI 现状与建议

当前仓库 `.github/workflows/` 只有 `backend-ci.yml`，**前端构建尚未纳入 CI**。建议新增 `ui-ci.yml`（与后端 job 并行）：

```yaml
name: ui-ci
on:
  push:
    paths: ['agentforge-ui/**', '.github/workflows/ui-ci.yml']
  pull_request:
    paths: ['agentforge-ui/**']

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: agentforge-ui
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: agentforge-ui/pnpm-lock.yaml
      - run: pnpm install --frozen-lockfile
      - run: pnpm build
```

### 5.7 常见问题

| 现象 | 排查 |
| --- | --- |
| 页面全是演示数据 | 顶栏"演示数据"标签看来源；后端是否启动、`VITE_PROXY_TARGET` 是否指对（默认 8080 可能被别的项目占用）、`/api/v1/auth/me` 是否真返回 AgentForge 的 JSON |
| 登录后立刻被踢回登录页 | 看 Network：`/auth/refresh` 是否失败；刷新失败会清 token；确认后端 JWT 密钥/过期时间一致 |
| 一直 403 | 当前账号权限码不含路由 `meta.permission`；开发期可让后端给 SUPER_ADMIN，或临时用 `/chat` 等低门槛页 |
| 请求提示"无法连接后端服务" | 后端未启动或代理目标错；检查 `pnpm dev` 控制台的 proxy 日志 |
| SSE 没有任何增量、最后一次性输出 | 反向代理缓冲：加 `proxy_buffering off` / `X-Accel-Buffering: no` |
| 中文变成乱码 / `vue-tsc` 报非法字符 | 源文件被写成 GBK；用 UTF-8 无 BOM 重存，不要用 PowerShell 5.1 `Set-Content` |
| `pnpm build` 报 `spawn EPERM` | 受限沙箱禁止子进程；换常规环境或 CI |
| 切页面后对话还在跑 | 检查是否漏写 `onBeforeUnmount(() => sse.stop())`；`stop()` 会同时 cancel 后端 run |
